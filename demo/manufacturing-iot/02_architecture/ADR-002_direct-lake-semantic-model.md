# ADR-002: Power BI セマンティックモデルを Direct Lake で構成する

| 項目 | 値 |
|------|-----|
| ステータス | 承認済 |
| 作成日 | 2026-10-30 |
| 作成者 | 猪野 勉 / Claude AI |
| 影響範囲 | 製造業 IoT デモ — Gold レイヤー、Power BI（`08_fabric/powerbi/`） |
| 関連ADR | MFG-001（取り込み方式）、MFG-003（配置の自動化） |

## 1. コンテキスト（必須）

工場長が毎朝 8:00 に前日の生産・品質・設備の状況を確認するダッシュボードを、Fabric 上の Gold テーブルから提供する。Power BI のセマンティックモデルの接続方式を決める必要がある。

| 要件・制約 | 内容 |
|-----------|------|
| 鮮度 | 毎朝 AM 8:00 までに前日分が見えること（SLA） |
| 容量 | 試用版・小さな F SKU でも動くこと。更新処理で容量を使いすぎないこと |
| 計算 | 比率（達成率・不良率など）は合計から再計算する（行の比率の平均は誤り） |
| 日付 | 前日比・7 日移動平均などのタイムインテリジェンスに日付テーブルが必要 |

## 2. 決定（必須）

**Lakehouse の SQL 分析エンドポイントに対する Direct Lake モードでセマンティックモデルを構成する。**

1. ファクトは Gold の `daily_production_kpi` と `equipment_health` をそのまま使う
2. ディメンション（`dim_date` / `dim_line` / `dim_equipment` / `dim_product` / `dim_status`）は、モデルの計算テーブルではなく、パイプラインの Notebook で Lakehouse の Delta テーブルとして作る
3. 比率は事前計算列を使わず、DAX メジャーで合計から再計算する。事前計算列は非表示にし、暗黙的なメジャーを抑止する
4. `dim_date` を日付テーブルとしてマークする

## 3. 理由

### 検討した代替案

| 案 | 概要 | 不採用理由 |
|----|------|-----------|
| **Direct Lake（採用）** | Delta テーブルを直接読む。インポートの複製が不要 | — |
| インポート | データをモデルに複製し、スケジュールで更新する | 更新のたびに容量を消費し、データが二重に持たれる。ETL 完了後の更新待ちで朝の鮮度に余裕がなくなる |
| DirectQuery | クエリのたびに SQL エンドポイントへ問い合わせる | 朝の同時閲覧で応答が遅くなりやすい。Direct Lake で足りる |
| Direct Lake ＋ モデル側の計算テーブル | 日付テーブルなどを DAX で作る | Direct Lake では計算テーブル・計算列に制約があり、SQL ビューを使うと DirectQuery に切り替わる（フォールバック）。ディメンションは Lakehouse 側で作るほうが確実 |

### 採用理由

- 更新（フレーミング）が数秒で終わり、容量の消費が小さい
- Gold テーブルを唯一のデータ源にでき、モデルとレイクの値がずれない
- ディメンションを ETL で作るので、参照整合性のチェック（孤立キー 0 件）をパイプラインに組み込める

## 4. 結果・影響

| 観点 | 影響 |
|------|------|
| ✅ 鮮度と容量 | 更新が速く、試用版容量でも動作した（2026-10-30 に確認） |
| ✅ 一貫性 | 比率をメジャーで合計から再計算するため、合計行・工場全体の値が正しい |
| ✅ 検証しやすさ | 全メジャー（80 個）を DAX で評価し、元データの合計値と一致することを確認できる |
| ⚠️ SQL エンドポイントの同期遅れ | Notebook 直後はテーブル一覧の同期が遅れ、モデルの更新が「Delta テーブルにアクセスできない」で失敗することがある（2026-10-30 に発生）。更新前に同期 API を呼ぶ必要がある |
| ⚠️ ディメンションの保守 | 日付テーブルの範囲やマスタの変更は ETL 側で行う必要がある |
| ⚠️ RLS とフォールバック | SQL エンドポイント側に RLS を設定すると DirectQuery に切り替わる可能性がある。行レベルの制御はセマンティックモデルの RLS を基本とする（`08_fabric/design/security-entra-id.md`）。条件は最新の仕様で要確認 |

### 再検討の条件

- データ量やメジャーの複雑さで、Direct Lake のガードレール（行数・メモリ）を超える場合
- SQL エンドポイントでの RLS が必須になり、フォールバックが許容できない場合
