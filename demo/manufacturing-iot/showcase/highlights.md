# ショーケース — 見どころハイライト

tf-etl-env デモの各フェーズにおける見どころをまとめる。

---

## 1. 要件定義（Phase 1）

**見どころ**: YAML 形式の構造化要件テンプレート

- データソース・ターゲット・SLA・ビジネスコンテキストを統一フォーマットで整理
- ⚡推論マーク: 不足情報を AI が推論し、明示的に確認を求める
- 要件テンプレートが後続フェーズの入力として一貫して使える

---

## 2. アーキテクチャ設計（Phase 2）

**見どころ**: ADR（Architecture Decision Record）の自動生成

- 5 つの代替案（日次バッチ / CDC / 時間バッチ / ストリーミング / ELT）を 7 次元で比較
- ADR-001 に意思決定の根拠を記録 — 設計判断のトレーサビリティ
- Mermaid フロー図でパイプライン全体を可視化
- ✅確定 / ⚡推論 マークで確実な情報と推論を区別

---

## 3. スキーマ設計（Phase 3）

**見どころ**: Medallion Architecture の段階的型強化

- Bronze: 全カラム STRING 型（ソースそのまま保持）
- Silver: 適切なデータ型 + 品質チェック + 計算列
- Gold: Star Schema の集計テーブル
- SCD Type 2 による設備マスタの履歴管理
- ER 図（Mermaid）で 5 テーブルの関係を可視化

---

## 4. 品質ルール設計（Phase 4）

**見どころ**: 6 次元品質フレームワーク + データ契約

- 完全性: 必須フィールドの NULL / 空文字チェック
- 正確性: 数値範囲チェック（温度 20〜80 度、振動 0.1〜5.0）
- 一貫性: フィールド間整合性（不良数 <= 実績数）
- 適時性: レコード作成日時の鮮度チェック
- 一意性: 複合キーによる重複検出
- 有効性: Enum 値チェック（ステータス、シフト）

品質スコア: A(>=95) B(>=85) C(>=70) D(>=50) F(<50) の 5 段階評価

---

## 5. パイプライン実装（Phase 5）

**見どころ**: 冪等性パターン + Dead Letter テーブル

### 冪等性

```python
# replaceWhere によるパーティション上書き
df.write.format("delta")
  .mode("overwrite")
  .option("replaceWhere", f"production_date = '{target_date}'")
  .save(table_path)
```

再実行しても安全。障害からの復旧が容易。

### Dead Letter パターン

```python
# 品質チェックで合格/不合格を分離
valid_df, error_df = validate_quality(typed_df)
# 不合格レコードは Dead Letter に保存
save_dead_letter(error_df, dead_letter_path, target_date)
```

エラーデータを削除せず分離。後で分析・修正可能。

### Frozen Dataclass

```python
@dataclass(frozen=True)
class TransformStats:
    input_count: int
    valid_count: int
    error_count: int
    error_rate: float
```

処理統計はイミュータブル。途中で書き換わらない安全な設計。

---

## 6. テスト実装（Phase 6）

**見どころ**: 品質ルール 1:1 対応のテスト

- 6 次元の品質ルールそれぞれに対応するテストクラス
- エッジケーステスト: NULL, 空文字, 境界値, 不正な型
- サンプル CSV を使った統合テスト（正常データの通過率 >= 90%）
- 全 80+ テストケースで品質ゲートを検証

---

## 7. 運用設計（Phase 7）

**見どころ**: 障害対応ランブック + データリネージ図

### 3 シナリオのランブック

1. **ソース CSV 未着** — 診断手順 + MES チーム連絡フロー
2. **品質スコア閾値超過** — Dead Letter 分析 SQL + パターン別対応表
3. **Spark ジョブ OOM** — 設定調整 + データ分割処理

### データリネージ図

MES → Bronze → Silver → Gold → Power BI の完全なデータフローを可視化。
品質ゲート不合格 → Dead Letter の分岐も含む。

### SLA 定義

鮮度・可用性・品質・完全性・パフォーマンスの 5 観点で SLA を定義。
段階的なエスカレーションフロー付き。

---

## tf-etl-env の価値まとめ

| 課題 | tf-etl-env の解決策 |
|------|-------------------|
| 設計判断が属人的 | ADR で自動記録、トレーサビリティ確保 |
| 品質チェックが後付け | 品質ルールを設計段階で定義、テストファースト |
| 障害対応が場当たり的 | ランブックを事前に生成、冪等性で安全に再実行 |
| ドキュメントが陳腐化 | コードと同時にドキュメント・図を生成 |
| 7 フェーズの抜け漏れ | 専用エージェント + コマンドで各フェーズを支援 |
